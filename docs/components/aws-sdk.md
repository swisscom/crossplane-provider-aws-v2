# AWS SDK for Go v2 and API models

## What it is

[aws-sdk-go-v2](https://github.com/aws/aws-sdk-go-v2) is the official Go SDK
of AWS. Every service is its own Go module
(`github.com/aws/aws-sdk-go-v2/service/<svc>`), generated by AWS from a
[Smithy](https://smithy.io) API model. The models are published in the same
repository (`codegen/sdk-codegen/aws-models/<model>.json`).

## Why

- SDK v1 (used by provider-aws) is end-of-support; v2 is the maintained SDK.
- The API model is the single source of truth for operations, shapes,
  documentation and enums. Generating from the **same version** of the model
  as the SDK module in `go.mod` guarantees that generated code compiles
  against that SDK.

## How it is used

**At build time** the code generator needs the model of a service:

1. `generator.ResolveServiceModule` adds the service module to the root
   `go.mod` if needed (`go get …@latest`) and reads its version and
   directory (`go list -m -json`).
2. The model file name is derived from the module's `ServiceID`
   (`api_client.go`), e.g. `"Service Catalog"` → `service-catalog`.
3. ACK's `EnsureModel` fetches the model from the git tag
   `service/<svc>/<version>` of aws-sdk-go-v2 and caches it in the user cache
   directory (`~/Library/Caches/provider-aws-v2-codegen` on macOS).

So **updating the SDK module in `go.mod` and running `make services`
updates the model**. Renovate bumps the modules; regenerate afterwards.

**At run time** the generated connector builds a client per reconcile:

```go
cfg, err := awsclient.GetConfig(ctx, kube, usage, cr, cr.Spec.ForProvider.Region)
client := svcsdk.NewFromConfig(cfg)
```

Controllers only see the generated `Client` interface (the operations they
use), which keeps fakes small.

## Types: API vs. SDK

The API types are generated by ACK and keep its conventions, which differ
from SDK v2:

| API types (`apis/…`) | SDK v2 |
|----------------------|--------|
| `*int64` | mostly `*int32` |
| `[]*string` | `[]string` |
| `[]*T` | `[]T` (values) |
| `*string` enums | typed string enums, zero value `""` |

Generated conversions handle this. In hand-written code use
`internal/utils/pointer` (`Int32`, `Int64`, `LateInitialize`, …) and
`aws.ToStringSlice` / `aws.StringSlice`.

## Pitfalls

- **Unexported input members.** Some SDK v2 inputs keep a model member
  unexported (e.g. `DestinationRegion` of the presigned-URL customization of
  rds and docdb). Generated code could not set it, so the generator parses
  `api_op_*.go` of the module and ignores those members automatically.
- **Errors.** No `awserr`: use `errors.As` with typed errors or
  `smithy.APIError` (`ErrorCode()`); wrap with `awsclient.Wrap`.
- **`cmp.Diff` on SDK structs panics** on the unexported
  `noSmithyDocumentSerde` field; see [testing.md](testing.md).
- **New model fields.** A newer model can add fields that provider-aws never
  had; they appear in the CRD automatically. See
  [porting-notes.md](../porting-notes.md#aws-api-changes-since-provider-aws).
